# Як агенту увійти під тестовим акаунтом, не вписуючи пароль у код

| | |
| --- | --- |
| Коли знадобиться | прогін кейсів агентом (`qa-agent-run`) і розвідка під акаунтами з `.env` |
| Площадки | всі (перевірено es, pt) |
| Роль | будь-який тестовий акаунт з `.env` (префікс змінних, напр. `TEST_BUYER_ES`, `TEST_SELLER_SEUR`) |
| Агенту можна виконувати | так — потрібен дозвіл на `mcp__playwright__browser_run_code_unsafe` у `.claude/settings.local.json` (QA додає через `/permissions`) |
| Перевірено | seller3, 2026-11-05 |
| Джерело | [задача 127593, 2026-11-05] |

## Передумови

- Дозвіл на `browser_run_code_unsafe` (без нього класифікатор безпеки Claude Code блокує вхід скриптом).
- Заповнені `<ПРЕФІКС>_LOGIN` / `<ПРЕФІКС>_PASSWORD` у `.env`.

## Кроки

1. Для кожної ролі — окрема вкладка з власним контекстом: `browser_tabs` → `new`, `isolatedContext` (напр. `buyer-es`, `seller-es`, `buyer-pt`).
2. У вкладці виконати фрагмент із `work/127593/04-cases/_common.md` → П-1: він відкриває `.env` у браузері через `file://`, бере значення за префіксом і заповнює форму входу. У тексті коду — тільки назви змінних.
3. Перевірити імʼя в шапці (напр. «test1 ID: 1075831», «Seller S. ID: 1082119»).

## Як перевірити результат

- Форма входу («Email», «Clave» / «Senha») зникла, у шапці — потрібний акаунт.

## Особливості площадок

- Вхід окремий для кожного хоста (es і pt — різні сесії).

## Відомі проблеми

- Інструмент дублює виконаний код у вивід: **не вписувати логін і пароль у код** (зокрема через згенерований файл) — вони потраплять у розмову.
- Файли для `browser_run_code_unsafe` → `filename` дозволені тільки всередині репозиторію; тимчасові файли із секретами не створювати.
- Сесії живуть, доки відкритий браузер Playwright; після перезапуску Claude Code — увійти знову.
- Тестовий Stripe Checkout (`cs_test_`) вимагає адресу платника — країну, вулицю, місто, індекс; без неї оплата не проходить [прогін 127593, 2026-11-05].
- Після зміни `.claude/settings.local.json` браузер MCP перезапускається: вкладка без `isolatedContext` — профіль, де покупець може бути залогінений. Роль перевіряти на старті кожного кейсу (гість — `GET /api/v1/addresses` 403; покупець — «ID: …» у шапці) [прогін 127593, 2026-11-05].
