- Формати номерів: **ES** — `1234ABC` або `A1234BC` (бекенд перевіряє регуляркою `^(?:\d{4}[A-Z]{3}|[A-Z]\d{4}[A-Z]{2})$`); **UA** — `АВ8517ВО`: 2 літери + 4 цифри + 2 літери, кирилиця або латиниця (бекенд транслітерує, формат не перевіряє). Маска поля — npm `@avtopro/regnum-input` за країною, вихідного коду в репозиторії немає [CodeWiki § Госномера-ЮА/Ввод-и-транслитерация/Формат-госномера-и-маска-ввода; зі слів QA, 2026-11-11].
- Сторінки: `/vin-code/`, `/vin-decoder/` — 1, 22, 28, 30, 618; `/check-auto/` — 1, 22, 30; `/carfax-report/` — тільки 1, 22 (інакше 404) [там само].

## Ліміти

**Пошук за VIN** (`SearchByVin`, `ExtraInfoByVin`) — `RateLimitManager`, ліміти за добу з таблиці `security.rate_limit_config` (у коді чисел немає). Категорії: гість і покупець без підтвердженого email — `Guest`; покупець із підтвердженим email — `Registered`; продавець і СТО — `Verified`. Перевищення — `429` з кодом `RateLimitExceeded_*`. На 22 перевірку вимкнено [CodeWiki § …/Лимиты-и-клиент].

**Держномер ES (Inforauto)** — власний ліміт [код `SearchByInfoautorManager.cs`, задача 129318; зі слів QA, 2026-11-11]:

| Хто | Результат |
| --- | --- |
| Номер уже є в локальному кеші (хтось його шукав) | результат одразу, **без ліміту й перевірок**, будь-кому, і гостю |
| Гість (`UserId == 75`) | `401`, текст «увійдіть, щоб виконувати більше запитів» |
| Авторизований без підтвердженого телефону (будь-який тип акаунта) | `403 PhoneNotConfirmed` → вікно введення / підтвердження телефону; після підтвердження пошук повторюється |
| Авторизований із підтвердженим телефоном | **3 запити**; окремо 3 з однієї IP-адреси (обидві умови) |
| Перевищення | `429` без тіла |

- «День» = **24 години від останнього врахованого запиту** (TTL лічильника в Redis перезаписується при кожному запиті), не календарна доба [зі слів QA, 2026-11-11: орієнтуємось на реалізацію].
- Лічильник збільшується до запиту в Inforauto — «номер не знайдено» теж витрачає спробу.
- Ліміт на IP спільний для всіх користувачів за цією IP — так задумано [зі слів QA, 2026-11-11].
- Ліміти введені проти парсингу держномерів, бо **запити до Inforauto платні** [зі слів QA, 2026-11-11]. Sandbox Inforauto немає — на стенді кожен новий номер є бойовим платним запитом [CodeWiki § …/Поиск-по-госномеру/Поля-ответа-Inforauto-и-отсутствие-sandbox].
- До задачі 129318: 5 запитів на годину на користувача і на IP, без перевірки телефону [CodeWiki; код master].
- **Як тестувати ліміт** [задача 129318, зі слів QA, 2026-11-11]:
    - перевірки `401` (гість) і `403` (без підтвердженого телефону) — безплатні, лічильник не витрачають;
    - кожен новий номер — платний запит до Inforauto; номер з бази — безплатно і без ліміту;
    - методу скинути лічильники немає: ліміт користувача «скидається» новим акаунтом, ліміт IP — тільки іншою реальною IP; скидання через 24 год перевіряється лише очікуванням;
    - cookie `debug_ip` IP для ліміту **не змінює** — ліміт бере `X-Forwarded-For` / адресу зʼєднання [код `SearchEngineController.cs:250`–`266`; `debug_ip` читає `LocationHelper.cs:34`];
    - ліміт 3 на IP спільний для всіх тестувальників з однієї мережі.
- Антипарсинг ендпоінт `PUT /api/v1/search/licensecarnumber` не перевіряє (немає `[EnableAntiParsing]`) — захист тільки цим лімітом [CodeWiki § Платформа/Антипарсинг].

## Де на сайті є поле держномера (регрес)

Спільний пошуковий движок `SearchEngine` / компоненти `CarSearch`, `RegnumVinSearch` [код, задача 129318]:

- основний пошук (шапка, сторінка пошуку);
- `/vin-code/`, `/vin-decoder/`, `/check-auto/`; Carfax (`/carfax-report/`, тільки 1, 22);
- гараж: банер додавання авто і форма авто;
- замовлення: вибір автомобіля;
- кошик / оформлення: вікно пошуку за VIN і форма адреси;
- запчастини для ТО;
- індикативна ціна.

У формах відгуків (виробник, СТО) і авторозбірок компонент вибору авто є, але поля держномера немає.
