# Інструкції для Claude у цьому репозиторії

Це QA-репозиторій проєкту AvtoPro. Тут не пишемо продакшн-код — тут готуємо і виконуємо тестування.

Скоуп — тільки сайт: десктоп і мобільна версія сайту. Мобільні застосунки (Vi.pro, планувальник СТО) — поза скоупом.

## Завжди

- Перед будь-якою QA-задачею прочитай `qa-context/PROJECT.md` і `qa-context/glossary.md`. Деталі — з `qa-context/domain/` за потреби.
- Артефакти задачі — тільки в `work/<ID задачі>/`. ID = номер задачі в Azure DevOps (наприклад `work/12345/`); немає номера — коротка назва латиницею (`work/cart-discount/`).
- Мова артефактів — українська. Назви кнопок і тексти інтерфейсу — дослівно, в лапках, як в UI.
- Наскрізні ID: дефекти вимог `RD-001`, питання `Q-001`, вимоги `REQ-001`, перевірки `CHK-001`, кейси `TC-001`, баги `BUG-001`. Нумерація — в межах задачі.
- Факти — тільки з документації, `qa-context/` або відповідей QA. Решта — з позначкою `[ПРИПУЩЕННЯ]`.

## Ніколи

- Не записуй паролі, токени, ключі та персональні дані в будь-які файли, крім `.env`.
- Не відкривай продакшн-URL через Playwright MCP і не вводь реальні платіжні дані.
- Не логінься на стенді під акаунтом, якого немає в `.env.example`: тестовий контур Stripe і Recalvi вмикається тільки для користувачів зі `StaticUserHelper.TestUsers`, під іншими акаунтами працюють бойові контури.
- Не створюй баги в Azure DevOps — їх заводить QA вручну з підготовленого тексту.

## Код AvtoPro

- Код AvtoPro підключається **тільки для читання** (пісочниця, `docs/sandbox-macos.md`). Не змінюй його файли і не запускай git-команд, що пишуть (`checkout`, `merge`, `fetch`, `commit`, `stash`, `clean`, `reset`).
- Код показує, що перевіряти; очікуваний результат — тільки з вимог. Розбіжність код ↔ вимога — питання або дефект.
- Секрети з коду й конфігів у qaPipeline не переносити.

## Документація (CodeWiki)

- CodeWiki — гілка `docs/wiki-kb-pilot`, окрема папка, тільки читання; шлях — `qa-context/sources.md`.
- Питання до документації спершу закривай сам скілом `qa-docs-lookup`; QA і аналітику — тільки те, чого в документації немає.

## Етапи pipeline

Нова задача — спершу `qa-pipeline`: він обирає маршрут S / M / L за ризиком (гроші, статуси, інтеграції = L).

0c. `qa-code-changes` → `00-input/code-changes.md` — зміни розробника в коді (якщо є гілка; у пісочниці)
1. `qa-req-review` → `01-review.md`, `01-answers.md` (маршрути M, L)
2. `qa-spec` → `02-spec.md` (маршрут L)
3. `qa-checklist` → `03-checklist.md` → `03-checklist.xlsx` (усі маршрути)
3b. `qa-dev-checklist` → `03-dev-checklist.md` — самоперевірка для розробника перед тестом (M, L; S — за бажанням)
4. `qa-agent-cases` / `qa-agent-run` → `04-cases/`, `05-runs/` — агент перевіряє новий функціонал; регрес — автотести
5. `qa-bug-report` → `bugs/` — текст для ручного перенесення в Azure DevOps

## Стан задачі — у файлах

Сесію можна перервати будь-коли, тому стан задачі не тримаємо в памʼяті розмови:

- після кожного завершеного кроку онови `work/<ID>/pipeline.md`: рядок у «Журнал» і «Де зупинились → Наступний крок»;
- факти, рішення і тестові дані, які QA повідомив у чаті, одразу записуй у `work/<ID>/00-input/notes.md` (з датою);
- непідтверджені кандидати в контекст — у `work/<ID>/context-candidates.md`, доки QA не відповість;
- відновлення — `qa-pipeline`: «продовжимо <ID>».

## Поповнення контексту

- Контекст поповнюється по ходу роботи, щоб QA переиспользовував факти і тестові дані в інших задачах. Правила — скіл `qa-context-update`.
- Кожен скіл pipeline наприкінці показує блок «Зберегти в контекст?», якщо знайшов щось корисне для інших задач.
- Якщо QA в чаті повідомляє факт про проєкт чи тестові дані — додай його в кандидати і покажи блок, навіть якщо не просив.
- Глосарій — активно: новий термін, синонім чи дослівна назва в інтерфейсі, яких немає в `glossary.md`, — завжди кандидат.
- Записуй у `qa-context/` тільки після підтвердження QA («так», «так 1, 3», «запамʼятай …»).
- Тестові дані спершу бери з `qa-context/test-data.md`, потім — з `work/<ID>/00-input/test-data.md`. Як отримати потрібний стан даних — `qa-context/howto/`.
- Внести багато знань без задачі — режим наповнення `/qa-context-intake`.
