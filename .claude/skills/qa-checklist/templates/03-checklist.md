## Опис

- **Функціонал:** <назва>
- **Що змінено:** <2–5 речень>
- **Задача:** <ID і посилання на Azure DevOps>
- **Маршрут:** S / M / L
- **Скоуп:** площадки — …; ролі — …; платформи — десктоп / мобільна версія сайту; регрес — входить / не входить
- **Стенд:** <версія>.seller<N>.vus.us
- **Джерела:** `02-spec.md` v1 / `01-review.md` / опис задачі
- **Питання:** <тільки маршрут S: неясності з міні-ревʼю, або «немає»>
- **Як заповнювати «Результат»:** Pass — очікуваний результат отримано; Fail — ні (заведіть баг, вкажіть номер у коментарі до клітинки); Blocked — неможливо перевірити; Skip — не перевіряли (вкажіть причину)

## Перевірки

> **Розділ** — роль або фінальний блок («Наскрізні сценарії», «Локалізація», «Регресійні перевірки»); у xlsx стає темним рядком-розділом.
> **Блок** — сценарій усередині розділу («1.1 Доступ»); у xlsx стає світлим рядком-підрозділом.
> **Вимога** — REQ / AC зі специфікації, `S-xx` з ревʼю або «Опис» (маршрут S).
> **Виконання** — агент / вручну / API / автотести; у xlsx не виводиться.
> **Результат** — необовʼязкова; Pass / Fail / Blocked / Skip від агента або QA; переноситься в xlsx.
