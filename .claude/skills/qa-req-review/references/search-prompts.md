# Промпти для пошуку відповідей у документації

Мета — QA вставляє промпт у Claude, де підключена документація (проєкт Claude з документами або Claude Code у цьому репозиторії з `docs/`), і отримує відповіді з цитатами. Або шукає сам за ключовими словами.

## Правила

- **Один промпт — один документ або одна тема.** 3–8 питань у промпті. Більше — розбий.
- **Адреса першою.** Вкажи документ і розділ із `qa-context/sources.md`, де шукати насамперед.
- **Питання самодостатні.** Назва сутності, роль, локаль, екран — без «це», «там», «вище».
- **Заборона домислів.** Промпт завжди вимагає «не знайдено», якщо прямої відповіді немає, і цитату, якщо є.
- **Формат відповіді — таблиця**, яку QA вставить у `01-answers.md` без переробки.
- **Ключові слова** — українською і мовою документа (англ. / рос. / ісп.), тексти UI, назви ендпоінтів і полів API, синоніми з глосарію.

## Шаблон

```text
Знайди в документації проєкту AvtoPro відповіді на питання нижче.
Задача: <ID> — <назва>.
Шукай насамперед у: <документ § розділ>; потім — у решті документації.

Питання:
Q-003. <питання>
Q-005. <питання>

Для кожного питання:
- Відповідь — коротко і тільки те, що прямо написано в документації.
- Джерело — документ і розділ; цитата до 2 речень.
- Якщо прямої відповіді немає — напиши «не знайдено». Якщо документи суперечать — «суперечність» і обидва джерела. Не роби висновків із непрямих ознак.

Формат — таблиця: Q | Відповідь | Джерело | Цитата | Статус (знайдено / не знайдено / суперечність).
```

## Для Swagger / API

Додай до питань, що саме потрібно: ендпоінт і метод, поля запиту й відповіді, обовʼязковість, валідації та ліміти, коди помилок і їхні тексти, права доступу.
