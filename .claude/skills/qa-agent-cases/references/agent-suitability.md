# Кому віддати перевірку: агент, вручну чи автотести

Агент (Claude Code + Playwright MCP на локальному компʼютері QA) перевіряє **новий функціонал задачі**, щоб прискорити тестування. Регрес закривають наявні автотести. Рішення приймається під час написання чек-листа — колонка «Виконання» в `03-checklist.md`.

## Значення колонки «Виконання»

| Значення | Коли |
| --- | --- |
| **агент** | Перевірка підходить агенту за критеріями нижче |
| **вручну** | Хоча б один стоп-фактор для агента, або вручну швидше |
| **API** | Перевірка через Swagger / DevTools без UI — агент або QA, за ситуацією |
| **автотести** | Регресійна перевірка, яку покривають наявні автотести; у ручний і агентний прогін не йде |

## Агенту — коли

Перевірка функціональна, а результат **однозначно перевіряється з тексту, числа, стану чи запиту**, і виконано хоча б одне:

- **багато варіантів даних** при однакових кроках — валідації полів, класи еквівалентності, граничні значення;
- **повтор під кількома ролями або площадками** — однакові кроки, різні акаунти чи хости (`es.`, `pt.`, `pl.` …);
- **ланцюжок кроків зі спільною передумовою** — кілька перевірок проходять за один сценарій (кошик → оформлення → сторінка замовлення);
- **перевірка того, чого не видно оком** — запити в Network (статус, тіло, поля), помилки в Console;
- **тексти і переклади** на кількох площадках — дослівне порівняння з очікуваним.

## Вручну — коли (стоп-фактори для агента)

- **Візуальне і субʼєктивне**: відповідність макету Figma, верстка, вирівнювання, кольори, «зручно», анімації. Функціональну перевірку мобільної версії (видно / клікається / працює) агент робить; візуальну — ні.
- **Поза браузером**: email, SMS, push, Telegram-бот, дзвінки.
- **Довгі очікування**: результат зʼявляється пізніше ніж за ~15 хвилин (TTL статусів, нічні задачі JobRunner). `sendorder` (5 хв) і трекінг (10 хв) — агенту можна.
- **Платіжні форми з 3-D Secure і зовнішні вікна банків** — нестабільно в автоматизації; простий тестовий платіж карткою Stripe без 3DS — можна, тільки під тестовим користувачем.
- **Дії, які псують спільні дані стенду** і їх не можна відкотити (масові зміни, видалення чужих даних).
- **Капча, антипарсинг (429 / 423)** — агент зупиняється.
- **Одинична проста перевірка** — один клік, один погляд: вручну швидше, ніж описати кейс.
- **Неоднозначний очікуваний результат** — спершу уточнити формулювання в чек-листі, а не віддавати агенту.

## Сумнівний випадок

Познач «агент» і додай у колонку «Перевірка» коротку причину сумніву — `qa-agent-cases` покаже такі рядки QA окремо перед написанням кейсів.
