## 1. Мета і скоуп

Держномери на avtopro.es парсять, а кожен запит до Inforauto платний. Пошук за новим держномером ES тепер доступний тільки авторизованому користувачу з підтвердженим телефоном — 3 запити за 24 години на користувача і 3 на IP. Без підтвердженого телефону замість пошуку відкривається вікно підтвердження телефону; після підтвердження пошук повторюється.

- **У скоупі:** площадка 30 avtopro.es; ролі — гість, покупець (без телефону / з непідтвердженим / з підтвердженим), продавець, СТО; платформи — десктоп і мобільна версія сайту.
- **Поза скоупом:**
    - перевірки обходу ліміту (номер з бази, `X-Forwarded-For`, антипарсинг) — ризики прийнято QA 2026-11-11 (RD-008);
    - вміст відповіді Inforauto і зіставлення марки / моделі — не змінювались;
    - мобільні застосунки.
- **Регрес:** входить — усі місця з полем держномера на 30, пошук за держномером і Carfax на 1 і 22, вікно підтвердження телефону в налаштуваннях акаунта (розділ 10).

### REQ-001. Гість: пошук за новим держномером недоступний

- **Джерело:** S-06; `qa-context/domain/vehicle-search.md` · **Пріоритет:** Високий
- **Площадки / ролі:** 30; гість
- **Опис:** гість не отримує даних за новим номером і бачить пропозицію увійти; вікно підтвердження телефону не відкривається.
- **Критерії приймання:**
    - AC-001.1 — **Given** avtopro.es, гість, номер `<новий ES>` **When** ввести номер у поле держномера основного пошуку і запустити пошук **Then** `PUT /api/v1/search/licensecarnumber` → `401`; під полем — «Se ha superado el límite de consultas por matrículas.     - AC-001.2 — **Given** те саме **When** пошук із банера сторінки `/vin-code/` **Then** `401` і той самий текст під полем
- **Коли перевіряти результат:** одразу
- **Статус:** готова

### REQ-002. Авторизований без підтвердженого телефону: вікно підтвердження замість пошуку

- **Джерело:** S-03, S-04; відповідь QA п. 1 (`01-answers.md`) · **Пріоритет:** Критичний · **BR:** BR-129318-01
- **Площадки / ролі:** 30; покупець, продавець, СТО без підтвердженого телефону
- **Опис:** запит за новим номером не виконується і не витрачає ліміт; відкривається вікно телефону, текст помилки під полем не показується.
- **Критерії приймання:**
    - AC-002.1 — **Given** avtopro.es, покупець **без телефону** в профілі **When** пошук за `<новий ES>` в основному пошуку **Then** відповідь `403`, тіло `{"Message":"Phone is not confirmed", код "PhoneNotConfirmed"}`; відкривається вікно з заголовком «Introduce tu número de teléfono», кнопки «Continuar» / «Cancelar»; під полем пошуку тексту помилки немає
    - AC-002.2 — **Given** покупець з **непідтвердженим** телефоном `<T>` **When** той самий пошук **Then** `403`; вікно відкривається одразу на кроці «Confirmación del teléfono» з номером `<T>`; є можливість повернутися до введення іншого номера
    - AC-002.3 — **Given** AC-002.1 **When** порахувати запити **Then** у Network один `PUT …/licensecarnumber` з `403`; запиту до Inforauto немає (у AppLog немає запису `inforcar` / `1681` для цього користувача) — ліміт не витрачено
    - AC-002.4 — **Given** у вікні введено номер з недопустимої країни (`+7…`) **When** «Continuar» **Then** помилка «No atendemos números de este país», перехід до коду не відбувається
    - AC-002.5 — **Given** поле номера телефону порожнє **When** «Continuar» **Then** помилка «Marque el número de teléfono»
- **Коли перевіряти результат:** одразу
- **Статус:** готова

### REQ-003. Підтвердження телефону у вікні і повтор пошуку

- **Джерело:** S-03, S-08, S-11; відповідь QA п. 1, п. 5; рішення по RD-007 (коди дає QA) · **Пріоритет:** Критичний · **BR:** BR-129318-01
- **Площадки / ролі:** 30; покупець, продавець без підтвердженого телефону
- **Опис:** після правильного коду вікно закривається, пошук за тим самим номером виконується автоматично; телефон стає підтвердженим.
- **Критерії приймання:**
    - AC-003.1 — **Given** вікно з AC-002.2, іспанський мобільний `<T>` у руках QA **When** запросити код **Then** підпис вікна — варіант для дзвінка: «…ingrese el código comunicado durante la llamada»; на `<T>` надходить дзвінок з кодом (не SMS); посилання «Enviar el código nuevamente» стає активним через 60 с
    - AC-003.2 — **Given** код отримано **When** ввести правильний код і «ENVIAR» **Then** вікно закривається без екрана успіху; автоматично виконується повторний `PUT …/licensecarnumber` з тим самим номером → `200`; у полі / видачі — знайдений автомобіль або «No se encontró un automóvil con este número de matrícula.»; повторного вікна телефону **немає**
    - AC-003.3 — **Given** AC-003.2 виконано **When** відкрити налаштування акаунта → особисті дані **Then** телефон `<T>` показано підтвердженим
    - AC-003.4 — **Given** вікно на кроці коду **When** ввести неправильний код **Then** у вікні помилка «Codigo erroneo»; вікно лишається відкритим; пошук не повторюється
    - AC-003.5 — **Given** 5 неправильних кодів поспіль **When** 6-та спроба **Then** помилка «Contar intentos fallidos terminados» (`429`); після нового запиту коду ввід знову можливий
    - AC-003.6 — **Given** покупець без телефону (AC-002.1) **When** ввести `<T>`, «Continuar», отримати і ввести код **Then** результат як в AC-003.2
- **Коли перевіряти результат:** одразу
- **Статус:** готова (ризик: пошук може знову дати `403` — перевіряє AC-003.2)

### REQ-005. Ліміт 3 запити на користувача

- **Джерело:** S-04; відповідь QA п. 1, п. 3 · **Пріоритет:** Критичний · **BR:** BR-129318-02, BR-129318-03
- **Площадки / ролі:** 30; авторизований з підтвердженим телефоном
- **Опис:** 3 запити за новими номерами виконуються; 4-й — відмова з повідомленням про ліміт.
- **Критерії приймання:**
    - AC-005.1 — **Given** покупець з підтвердженим телефоном, лічильники користувача й IP = 0 **When** 3 пошуки за трьома різними новими номерами **Then** три відповіді `200`
    - AC-005.2 — **Given** AC-005.1 **When** 4-й пошук за новим номером в основному пошуку **Then** `429` без тіла; під полем — «Se ha superado el límite de consultas por número de matrícula. Intente nuevamente dentro de una hora.» (`SearchErrorExceededLimitNumberQueries`); формулювання «dentro de una hora» суперечить вікну 24 год — перевірити фактичний текст, невідповідність → баг (RD-002, Q-002)
    - AC-005.3 — **Given** AC-005.1 **When** 4-й пошук у банері `/vin-code/` **Then** `429`; під полем — «Se ha superado el límite de consultas por número de matrícula. Intente nuevamente dentro de una hora.» (`SearchRegnumRequestsExceeded`); RD-002 — як AC-005.2
    - AC-005.4 — **Given** ліміт користувача вичерпано на IP-1 **When** 4-й пошук того ж користувача з **IP-2** (лічильник IP-2 = 0) **Then** `429` — ліміт діє на користувача незалежно від IP
    - AC-005.5 — **Given** з 3 запитів один за номером ES правильного формату, якого немає в Inforauto **When** 4-й запит **Then** `429` — «номер не знайдено» теж витрачає спробу [QA: як у реалізації]
- **Коли перевіряти результат:** одразу
- **Статус:** готова; текст — під питанням (Q-002)

- **Статус:** готова

### REQ-007. Скидання ліміту через 24 години від останнього врахованого запиту

- **Джерело:** S-04; відповідь QA п. 3 · **Пріоритет:** Середній · **BR:** BR-129318-03
- **Площадки / ролі:** 30; авторизований з підтвердженим телефоном
- **Критерії приймання:**
    - AC-007.1 — **Given** 3-й врахований запит зроблено в момент `t` **When** пошук за новим номером у `t + 24 год + 5 хв` (той самий користувач, IP з лічильником 0 або той самий IP) **Then** `200`
    - AC-007.2 — **Given** 3-й врахований запит у момент `t` **When** пошук у `t + 23 год` **Then** `429`
    - AC-007.3 — **Given** після вичерпання ліміту зроблено відхилені запити (`429`) у `t + 1 год` **When** пошук у `t + 24 год + 5 хв` **Then** `200` — відхилені запити вікно не продовжують [QA: як у реалізації]
- **Коли перевіряти результат:** через 24 год; без доступу до Redis — окремий прогін наступного дня (Q-005)
- **Статус:** готова
