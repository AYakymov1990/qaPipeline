## Мета

Довести, що автоскасування замовлення Seur, поки гроші в холді, повертає їх покупцю (`reversed`) — і коли продавець не підтвердив, і коли підтвердив, але не відправив.

## Передумови

- Як у TC-022; QA API — `qa-context/howto/order-dates.md` (дозвіл QA 2026-11-10), запити з вкладки покупця (`fetch`).

## Тестові дані

T01, «28001», картка 4000 0072 4000 0007, 09/30, CVC 111. Два окремі замовлення:

| Варіант | Стан | Дії QA API | CHK |
| --- | --- | --- | --- |
| 1 | «WaitingDeparture» (після «CONFIRMAR») | `shift-date` `shiftDay=-5` → `emulate-auto-reject-order` | CHK-154 |
| 2 | «WaitingSellerComfirmation» (без «CONFIRMAR») | `shift-date` `shiftDay=-5` (дедлайн статусу — 94 год) → `emulate-auto-reject-order` | CHK-155 |

## Кроки

Для кожного варіанта:

1. **Покупець.** П-2 (T01), П-3 («28001»), П-4 — оплати. Номер замовлення; Профіт — `holded`.
2. Варіант 1: **продавець** → «CONFIRMAR» → «WaitingDeparture»; Профіт — `holded`.
3. **Покупець (вкладка).** `PATCH /api/v1/qa/orders/shift-date?orderId=<id>&shiftDay=-5` → статус відповіді.
4. `GET /api/v1/qa/orders/emulate-auto-reject-order?orderId=<id>` → статус і текст відповіді дослівно (очікується «Успех! Предоплата: …»; «Не закончилось время жизни заказа…» — ще `shift-date -5` і повтор, разом не більше `-15`).
5. Статус замовлення (`Status.Status`); повідомлення на сторінці замовлення — дослівно і в порядку появи.
6. Профіт — «Статус» (до 2 хв).
7. **Продавець.** «Finanzas» → «Historial de operaciones» — запис по замовленню.

## Очікуваний результат

- [ ] **CHK-154** — варіант 1: «Rejected»; Профіт `holded` → `reversed`; у продавця в «Historial de operaciones» запису немає.
- [ ] **CHK-155** — варіант 2: «Rejected»; Профіт `holded` → `reversed`; повідомлення в тому самому порядку, що й при ручному скасуванні (скасування → звільнення коштів).
- [ ] У Console немає помилок; у Network немає 5xx.

**Коли перевіряти:** одразу; Профіт — до 2 хв після кроку 4.
