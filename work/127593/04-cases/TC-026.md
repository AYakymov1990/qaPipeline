## Мета

Довести, що після «PEDIDO ENTREGADO» (ТТН Seur, Профіт `succeeded`) скасування покупцем не повертає гроші автоматично і покупець бачить текст зі зверненням у підтримку.

## Передумови

- Стенд: `${BASE_URL_ES}`; спільні кроки — `_common.md`.
- Замовлення Seur T01 / «28001» у статусі «Departed» з ТТН і Профітом `succeeded` — після TC-022 (або 10787679 з повторної перевірки 2026-11-10, якщо Профіт `succeeded`).
- QA API — `qa-context/howto/order-dates.md` (дозвіл QA 2026-11-10): запити з вкладки покупця (`fetch`, cookie сесії).
- Профіт — `qa-context/howto/payment-status.md`.

## Тестові дані

- Зсув дат: `PATCH /api/v1/qa/orders/shift-date?orderId=<id>&shiftDay=-5` (у минуле); якщо дії відмови ще немає — ще раз `-5`, разом не більше `-15`.

## Кроки

1. Профіт для замовлення — «Статус» (очікується `succeeded`). Покупець: сторінка замовлення — доступні дії (дії відмови немає — це № 88).
2. **Покупець.** Виклич `shift-date` з `shiftDay=-5` → статус відповіді. Онови сторінку замовлення; переглянь дії.
3. Дія відмови / скасування зʼявилась — натисни, у діалозі вкажи причину, підтвердь. Зафіксуй запит і відповідь, тексти діалогу й сторінки — дослівно.
4. Статус замовлення (`Status.Status`), `TrackingInfo`; повідомлення на сторінці замовлення.
5. Профіт — «Статус» (до 2 хв).
6. **Продавець.** Сторінка замовлення — статус, дії.

## Очікуваний результат

- [ ] **CHK-120** — після зсуву дат у покупця є дія відмови; після неї статус замовлення зафіксовано (дослівно в звіт); Профіт лишається `succeeded`, `reversed` не зʼявляється; покупець бачить текст зі зверненням у підтримку / до продавця щодо повернення.
- [ ] У Console немає помилок; у Network немає 5xx.

**Коли перевіряти:** одразу; Профіт — до 2 хв після кроку 3.

## Для QA після прогону

- Лог: сбор у SEUR скасовано (`Seur:CancelShipment`, `Cancelled`) — частина CHK-120 з логу.

## Обмеження

Див. `_common.md`. QA API — тільки `shift-date` для цього замовлення; інші виклики `api/v1/qa/*` не робити. 400 «Аккаунт не тестовый» або 401/403 — BLOCKED.

## Очищення

- Номер замовлення і підсумковий стан у звіт.
